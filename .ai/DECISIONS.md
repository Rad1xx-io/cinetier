# Решения — что и почему

## 2026-08-26 — Custom убран из навигации
Custom был добавлен в топ-навигацию (десктоп: сегментированная пара с
Tier List; мобильный таб-бар: место Settings) в PR #39/#41. Затем
осознанно откачен в PR #42 — Custom НЕ должен быть отдельным пунктом
навигации. Вместо этого — видимая кнопка "Custom" в тулбаре страницы
обычного тир-листа. Settings вернулся на своё место в мобильном
таб-баре. Не переоткрывать этот вопрос без явного нового запроса.

## Удаление поста — общее, не только для custom
deletePost сделан универсальным для любого поста (PR #40), а не только
для custom — чтобы не объяснять, почему фото удалить можно, а фильм
нет.

## 2026-08-27 — Снепшот обычных постов: структура заморожена, каталог — нет
custom_list_publications (013) уже замораживала структуру кастомных
досок, но не картинки — они резолвятся живьём через RLS/is_blocked()/
hidden_at. PR #45 (миграция 014, ranked_title_publications) делает то
же самое для обычных постов: снепшот хранит только tmdbId/mediaType/
tier/order — какой тайтл в каком тире и в каком порядке на момент
Publish. Название, постер, дата выхода НЕ замораживаются — это
каталожные данные, они резолвятся живьём из ranked_titles точно так же,
как картинки кастомных карточек. Тайтл, убранный автором из рейтинга
после публикации, просто не находится в live-выборке и пропадает из
поста — тот же принцип, что и у пропавшей custom-карточки, без
отдельного механизма модерации для этого случая.

Рычаг "убрать весь борд из постов" уже существовал до этой миграции:
ranked_titles и так гейтится на is_public профиля (миграция 004).
Ставить профиль приватным убирает автора из ЛЮБОГО его поста
одновременно — второй отдельный переключатель для этого не нужен и не
добавлялся.

Фикс только вперёд: посты, опубликованные до 014, снепшота не имеют и
продолжают жить по старой live-логике, пока автор не пересоздаст пост
(Delete Post + Publish заново, механизм из PR #40). На проде на момент
миграции — 2 таких поста (movie, game).

Решение не переоткрывать без явного запроса: снепшот кастомных досок и
снепшот обычных постов — сознательно РАЗНЫЕ таблицы
(custom_list_publications / ranked_title_publications), не общая
абстракция — формы данных разные (тиры+карточки vs список
tmdbId+tier+order), и объединять их в одну таблицу ради DRY не
стали.

## 2026-08-28 — Статические страницы /about, /privacy, /terms
Запрошены с `generateMetadata`, но `app/discover/page.tsx` (эталон для
страниц без динамических параметров) использует обычный
`export const metadata: Metadata` — `generateMetadata` в кодовой базе
зарезервирован под страницы с динамическими параметрами
(`app/u/[username]/page.tsx`). Сделано по факту паттерна, не по
буквальной формулировке запроса — это ближе к духу "по существующему
паттерну в app/", чем `generateMetadata` на статической странице.

/privacy — kseronikseu@gmail.com. Этот адрес ранее в сессии фигурировал
как чужой тестовый аккаунт, задетый багом утечки данных; явно
переспрошено и подтверждено пользователем — это его собственный второй
личный аккаунт, не опечатка. Не переспрашивать снова без причины.
